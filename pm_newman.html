Newman a fondo

Newman es el ejecutor de colecciones de Postman por línea de comandos. Es open source, funciona sobre Node.js y no necesita una cuenta de Postman: ejecuta los archivos .json exportados. Aquí verás cómo instalarlo en Windows, cómo ejecutarlo con todas sus opciones útiles, cómo generar reportes y cómo automatizarlo dentro de la red de la empresa.
1Descargar Node.js (versión LTS)Entra a nodejs.org → Download → versión LTS (la estable). Dos opciones:
• Windows Installer (.msi): instalación normal. Suele pedir permisos de administrador.
• Standalone binary (.zip): se descomprime en una carpeta propia, sin administrador. Útil en equipos corporativos.
2InstalarCon el .msi: Siguiente → Siguiente, dejando marcada la opción Add to PATH.
Con el .zip: descomprimir en C:\herramientas\node y agregar esa carpeta al PATH de tu usuario (Inicio → “variables de entorno” → Editar las variables de entorno de esta cuenta).
3Verificar Node y npmAbre una terminal nueva (Símbolo del sistema) y verifica las versiones. npm es el instalador de paquetes que viene con Node.
4Instalar Newmannpm install -g newman. El -g lo instala de forma global para tu usuario, para usarlo desde cualquier carpeta. No necesita administrador.
5Instalar el reporte HTMLnpm install -g newman-reporter-htmlextra agrega el reporte HTML navegable.
6Comprobar que funcionanewman -v muestra la versión. Si aparece, Newman quedó listo.

1Exportar desde PostmanColección → ⋯ → More → Export collection → Other → Collection v2.1. Environment: primero ☁ Share en cada valor que Newman necesita (si no, se exporta vacío), luego ⋯ → Export. Guarda los dos .json en una carpeta del proyecto.

      
2Ejecución básicanewman run coleccion.json -e environment.json. Igual que el Runner, pero sin abrir Postman.

      
3Solo una carpeta, varias veces--folder elige la carpeta (se puede repetir) y -n la cantidad de iteraciones.

      
4Secretos por parámetro--env-var "apiKey=…" reemplaza una variable al ejecutar. Así la clave no queda escrita en el archivo del environment ni en el repositorio.

      
5Detener al primer error--bail corta la ejecución en cuanto falla un test: no sigue llenando el reporte de errores en cadena.

      
6Guardar las variables resultantes--export-environment escribe el environment al terminar, con los valores que guardaron los scripts (por ejemplo, el último petId).

Opciones más útiles

  

    
-e archivo.jsonEnvironment a usar.

    
-g globals.jsonVariables globales exportadas.

    
--folder "Nombre"Ejecutar solo esa carpeta. Se puede repetir para varias.

    
-n 3Iteraciones.

    
-d datos.csvArchivo de datos (CSV o JSON): una iteración por fila.

    
--env-var "clave=valor"Sobrescribe una variable del environment al ejecutar (ideal para secretos desde Jenkins).

    
--delay-request 200Espera en ms entre requests.

    
--timeout-request 10000Tiempo máximo de cada request en ms.

    
--bailDetener al primer fallo.

    
--export-environment salida.jsonGuardar el environment final.

    
--suppress-exit-codeTerminar con código 0 aunque fallen tests (para que el pipeline no se detenga; úsalo con criterio).

    
--verboseMuestra el detalle de cada request y response: útil para depurar.

  







  

    

      
1CLI (en pantalla)Es el reporte por defecto: lo que ves en la terminal. Bueno para mirar, no para guardar.

      
2HTML (htmlextra)Un archivo .html con resumen, gráficos y el detalle de cada request y test. Ideal como evidencia o para compartir.

      
3JUnit (para Jenkins)Un .xml estándar que Jenkins, Azure DevOps y otras herramientas de CI entienden y muestran como resultados de prueba.

      
4AllureReporte profesional con historial y tendencias. Necesita newman-reporter-allure y la herramienta Allure (que requiere Java) para generar la vista.

      
5Varios a la vez-r cli,htmlextra,junit genera los tres en una sola ejecución.

1Scripts de npmEn package.json se guardan los comandos largos con un nombre corto: npm run test:crud. Todo el equipo ejecuta exactamente lo mismo.

      
2Un archivo .batejecutar_pruebas.bat agrupa los pasos (ir a la carpeta, ejecutar, generar reporte) en un doble clic.

      
3Programador de tareas de WindowsEjecuta el .bat solo, por ejemplo todos los días a las 7:00. Corre dentro de la red, así que sí alcanza APIs internas, a diferencia de las ejecuciones agendadas en la nube de Postman.

      
4JenkinsEn un pipeline, el mismo comando corre en cada despliegue y publica el JUnit. Los secretos se pasan con --env-var desde las credenciales de Jenkins.

    "test:datos": "newman run … --folder \"Datos desde archivo\" -d datos/mascotas.csv",
    "test:reporte": "newman run … -r cli,htmlextra,junit …"
  }
}

      
⬇ package.json

    
🪟 ejecutar_pruebas.bat

@echo off
cd /d "%~dp0"
if not exist reports mkdir reports
call newman run "Taller Petstore.postman_collection.json" ^
  -e "Petstore - QA.postman_environment.json" ^
  --folder "CRUD Mascota" ^
  -r cli,htmlextra,junit ^
  --reporter-htmlextra-export reports\reporte.html ^
  --reporter-junit-export reports\junit.xml
rem El código de salida indica si pasaron todos los tests
exit /b %ERRORLEVEL%

🔒 “La ejecución de scripts está deshabilitada”En PowerShell, npm instala Newman como un script .ps1 que la política de la empresa puede bloquear.

newman : No se puede cargar el archivo C:\Users\…\AppData\Roaming\npm\newman.ps1 porque la ejecución de scripts está deshabilitada en este sistema.

      Solución: usar el Símbolo del sistema (cmd), o escribir newman.cmd en lugar de newman. Cambiar la política de PowerShell solo con autorización de seguridad.

    
❓ “newman no se reconoce como un comando”La carpeta de npm no está en el PATH, o la terminal se abrió antes de instalar.

"newman" no se reconoce como un comando interno o externo,
programa o archivo por lotes ejecutable.

      Solución: cerrar y abrir una terminal nueva. Si sigue, agregar %APPDATA%\npm al PATH de tu usuario.

    
🌐 npm no descarga (proxy de la empresa)La red sale a internet por un proxy y npm no lo conoce.

npm ERR! code ETIMEDOUT
npm ERR! network request to https://registry.npmjs.org/newman failed

      Solución: configurar el proxy que indique el área de infraestructura:

npm config set proxy http://proxy.empresa.local:8080
npm config set https-proxy http://proxy.empresa.local:8080

    
📜 Error de certificadoLa empresa inspecciona el tráfico con su propio certificado y Node no lo reconoce.

npm ERR! code SELF_SIGNED_CERT_IN_CHAIN
Error: unable to get local issuer certificate

      Solución: pedir el certificado raíz de la empresa (.pem) e indicarlo, en vez de desactivar la verificación:

npm config set cafile C:\certs\ca-empresa.pem
newman run … --ssl-extra-ca-certs C:\certs\ca-empresa.pem

  

  
⚠ Evita npm config set strict-ssl false y newman --insecure como solución permanente: desactivan la verificación de certificados y abren la puerta a ataques de intermediario. Úsalos, si acaso, solo de forma puntual en ambientes de prueba y con autorización.






  Idea clave: Newman convierte la colección en algo que se ejecuta sin intervención humana: en tu PC con un doble clic, en un servidor con el Programador de tareas o en cada despliegue con Jenkins, siempre dentro de la red y con reportes como evidencia.
