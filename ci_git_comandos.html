Git: los comandos que necesitas

Git guarda el historial como una cadena de commits: cada uno apunta al anterior. Una rama es solo una etiqueta que apunta a un commit, y HEAD indica en qué rama estás parado. Prueba los comandos y mira qué le pasa al historial en tu PC y en GitHub.

Dos formas de deshacer

↩️ git revert <commit>Crea un commit nuevo que hace lo contrario. El historial queda intacto y se puede subir sin problemas.
Úsalo para deshacer algo que ya está en GitHub.
⏪ git resetMueve la rama hacia atrás, como si esos commits no hubieran existido.
• --soft: conserva los cambios listos para un nuevo commit.
• --hard: borra también los cambios de tus archivos.
Úsalo solo con commits que todavía no subiste.
⚔️ ConflictosSi tú y otra persona cambian las mismas líneas, git merge o git pull se detienen y marcan el archivo con <<<<<<<, ======= y >>>>>>>. Eliges qué queda, borras las marcas, y haces git add + git commit. Con colecciones de Postman (JSON grandes) conviene no editar la misma colección a la vez y hacer pull antes de empezar.
🌿 ¿Por qué usar ramas?Trabajas en feature/login sin romper main, que es la que ejecuta Jenkins. Cuando todo funciona, lo unes con un merge (en equipos, mediante un Pull Request en GitHub, donde otra persona lo revisa antes de unirlo).

Chuleta de comandos

Empezar

git config --global user.name "…"Tu nombre en los commits (una vez)
git initConvertir una carpeta en repositorio
git clone <url>Descargar un repositorio existente
git remote add origin <url>Conectar con GitHub

Guardar cambios

git statusQué cambió y qué falta guardar
git diffVer las líneas cambiadas
git add <archivo> / .Pasar cambios a staging
git commit -m "…"Guardar una foto en el historial
git stash / stash popGuardar cambios a un lado y recuperarlos

Ramas

git branchListar ramas (* = la actual)
git switch -c <rama>Crear una rama y pasarse a ella
git switch <rama>Cambiar de rama
git merge <rama>Unir esa rama a la actual
git branch -d <rama>Borrar una rama ya unida

Sincronizar

git pushSubir tus commits
git push -u origin <rama>Subir una rama nueva por primera vez
git fetchTraer novedades sin mezclarlas
git pullfetch + merge: traer y unir

Ver el historial

git log --oneline --graphHistorial compacto con ramas
git show <commit>Qué cambió en un commit
git blame <archivo>Quién cambió cada línea

Deshacer

git restore <archivo>Descartar cambios sin guardar
git restore --staged <archivo>Sacar de staging
git revert <commit>Deshacer con un commit nuevo
git reset --soft HEAD~1Deshacer el último commit (no subido), conservando cambios
Rutina segura: pull antes de empezar → trabajar → status → add → commit → pull → push. Y para deshacer algo que ya está en GitHub: revert, nunca reset.
