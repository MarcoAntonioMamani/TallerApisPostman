Tu primer job: “hola-jenkins”

Antes de conectar repositorios y pruebas, un job sencillo para conocer cada parte de Jenkins: crear un item, escribir un pipeline, ejecutarlo, leer la consola, ver el workspace y los artefactos, usar parámetros y entender un fallo. No clona nada: el código del pipeline se escribe directamente en Jenkins.
1El DashboardLa página principal: lista de jobs con su estado, y el menú de la izquierda.
2New ItemNombre hola-jenkins, tipo Pipeline → OK.
3General: descripciónUna descripción y, opcional, Discard old builds. Todo lo demás se puede dejar como está.
4Pipeline scriptDefinition Pipeline script y pega el código. Cuatro stages: saludar, ver información del build, crear un archivo y llamar a una API con curl.
5Build NowGuarda y ejecuta. La Stage View muestra cada etapa en vivo con su tiempo.
6Console OutputEl log completo del build. Es lo primero que se revisa cuando algo falla.
7Workspace y artefactosLa carpeta donde trabajó el build y los archivos que se guardaron como evidencia.
8Variables de JenkinsJenkins entrega datos del build como variables de entorno: número, nombre del job, URL…
9Build with ParametersDesde el segundo build aparece el formulario. Cambia el nombre y el ambiente, y ejecuta.
10Un build que fallaRompemos un paso a propósito para aprender a leer el error.
11Pipeline SyntaxEl generador de código de Jenkins: eliges un paso en un formulario y te da la línea para pegar.
Lo que ya sabes: crear un job, escribir y ejecutar un pipeline, leer la consola, encontrar archivos en el workspace, guardar artefactos, usar parámetros y diagnosticar un fallo. El siguiente paso es el mismo pipeline… pero leído desde GitHub y ejecutando Newman.
