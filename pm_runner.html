Collection Runner: ejecutar todas las pruebas de un clic

Hasta ahora enviamos los requests uno por uno. El Collection Runner ejecuta una colección o carpeta completa, en orden, corre todos sus scripts y tests, y muestra un reporte con lo que pasó y lo que falló. Es el paso de “probar a mano” a ejecutar una suite de pruebas.
🔁 Regresión en segundosDespués de cada cambio en la API, se vuelve a ejecutar todo y se ve de inmediato si algo se rompió.
🔢 IteracionesLa misma colección se puede ejecutar N veces seguidas; con datos generados, cada vuelta prueba datos distintos.
📋 EvidenciaEl reporte muestra cada request, su status, su tiempo y cada test en PASS o FAIL, y se puede exportar.

Cómo leer el reporte

🟢 Todo en PASSLa API respondió como se esperaba en todos los requests. Revisa también los tiempos: una suite que pasa pero tarda el triple que ayer es una alerta.
🔴 Algún FAILAbre el request que falló y lee el mensaje: dice qué llegó y qué se esperaba. Recuerda que un FAIL al inicio puede arrastrar a los siguientes (si no se creó la mascota, tampoco se puede consultar).
📤 ExportarCon Export Results descargas el reporte en JSON, como evidencia de la ejecución.
Idea clave: una colección bien armada (variables, datos generados y tests en cada request) se convierte en una suite de regresión que se ejecuta de un clic, cuantas veces haga falta. Desde aquí todo es automatizar: controlar el orden, programarla, ejecutarla desde la terminal y alimentarla con archivos de datos.
