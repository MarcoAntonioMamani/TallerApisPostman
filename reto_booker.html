TU MISIÓN
El Hostal Andino está por lanzar su app de reservas y te contrató como QA de APIs. Antes de salir a producción necesita saber si su API crea, consulta, busca, modifica y elimina reservas correctamente, si está protegida contra cambios sin autorización y si funciona con distintos huéspedes.

Vas a construir en Postman una colección de pruebas automatizadas que lo demuestre, ejecutarla completa con el Collection Runner y reportar los defectos que encuentres.

2

Crea la colección y sus carpetas

La estructura que entregarás

Crea la colección Reto Hostal Andino con dos carpetas. Los nombres de los requests llevan número para que el orden quede claro:

🗂 Reto Hostal Andino ├─ 📁 Reserva completa ← se ejecuta con huespedes.csv (paso 4) │ ├─ 01 Login │ ├─ 02 Crear reserva │ ├─ 03 Consultar reserva │ ├─ 04 Buscar reserva por nombre │ ├─ 05 Actualizar sin token (negativo) │ ├─ 06 Actualizar reserva │ ├─ 07 Eliminar reserva │ └─ 08 Verificar eliminación └─ 📁 Defectos encontrados ← tus hallazgos (paso 5)

💡 Test común para toda la colección: en la colección → pestaña Scripts → Post-response, agrega un test "Responde en menos de 3 s" que valide el tiempo de respuesta. Se aplicará a todos los requests.

3

Construye los 8 requests

Haz clic en cada uno para ver qué debe tener

Todos usan {{baseUrl}}. Los datos del huésped ({{firstname}}, {{lastname}}, {{totalprice}}, {{depositpaid}}, {{additionalneeds}}) vienen de las columnas del CSV. Mientras construyes, puedes probarlos con Send creando esas variables temporalmente en tu environment; al final, en el paso 4, las tomarán del archivo.

4

Ejecuta la carpeta con el archivo de datos

La prueba de que todo está automatizado
  1. Si creaste variables temporales de huésped en el environment, elimínalas: deben venir del CSV.
  2. Sobre la carpeta Reserva completa → ⋯ → Run folder.
  3. En Test data file → Select File elige huespedes.csv y revisa el Preview: 6 columnas y 5 filas.
  4. Verifica que Iterations sea 5 y presiona Run.

✅ Resultado esperado: 5 iteraciones × 8 requests = 40 requests, con todos los tests en verde. El 403 del request 05 y el 404 del request 08 aparecen en rojo como status, pero sus tests pasan: eran los resultados esperados.

💡 Si algo falla en el Runner
  • ¿Una variable sale sin reemplazar ({{firstname}} literal)? El nombre de la columna del CSV no coincide exactamente con el de la variable.
  • ¿El 03 dice que el precio no coincide? Los valores del CSV llegan como texto: compara con Number(...).
  • ¿Falla el 06 o el 07 con 403? El token no se está guardando o no se envía en el header Cookie.
  • Abre la Postman Console (Ctrl+Alt+C) para ver exactamente qué se envió.
5

Caza de defectos

Lo que distingue a un QA: encontrar lo que no funciona como debería

Esta API tiene defectos reales: respuestas que no siguen las buenas prácticas de REST que vimos en el taller. Encuentra al menos 3. Para cada uno:

  1. Crea un request en la carpeta Defectos encontrados con un nombre que diga qué debería pasar. Ejemplo de formato: D1 <acción> debería responder <status correcto>.
  2. Escribe un test que valide el comportamiento correcto. Ese test debe fallar: el fallo es la evidencia del defecto.
  3. Regístralo en una tabla como esta, en un documento corto (Word, PDF o el formato que prefieras):

💡 Pista 1: dónde buscarRevisa el status code de cada operación, incluso de las que “funcionan”. ¿Coincide con la diapositiva de status codes? ¿Qué debería responder una creación? ¿Y un borrado?
💡 Pista 2: casos negativosPrueba lo que un usuario no debería poder hacer bien: credenciales incorrectas, un body incompleto, valores sin sentido. Un error del cliente debería ser un 4xx, nunca un 5xx.
💡 Pista 3: más allá del statusExiste un endpoint de “salud” del servicio en la documentación. ¿Qué status responde? ¿Tiene sentido?
6

Entrega

Comprime todo en un solo archivo: Reto_TuNombre.zip
  1. La colección: ⋯ → Export → Collection v2.1.
  2. El environment: ⋯ → Export. Antes, borra el current value del token.
  3. La evidencia del Runner: captura de pantalla del resultado de las 5 iteraciones, o el reporte HTML de Newman si lo tienes instalado.
  4. El documento de defectos con la tabla del paso 5.
🔐 Seguridad: no incluyas tokens ni contraseñas reales en ningún archivo. Las credenciales de esta API son públicas de práctica, pero acostúmbrate a revisar qué exportas antes de compartirlo.
