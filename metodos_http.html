PUT vs PATCH

PUT — reemplaza todo

Se envía el recurso completo. Lo que no se envía puede quedar vacío o con su valor por defecto.

PUT /clientes/2
{ "nombre": "Luis Mamani",
  "ciudad": "Cochabamba",
  "estado": "activo" }
PATCH — modifica una parte

Se envían solo los campos que cambian. El resto se mantiene igual.

PATCH /clientes/2
{ "estado": "inactivo" }

Resumen

MétodoAcción¿Lleva body?¿Idempotente?Respuesta típica

DELETEEliminarNoSí — el resultado final es el mismo204 No Content
¿Qué es idempotente? Que repetir la misma petición varias veces deja el servidor en el mismo estado que hacerla una vez. Si se envía DELETE /clientes/3 dos veces, el cliente 3 sigue eliminado (la segunda vez responde 404, pero nada más cambió). En cambio, enviar POST /clientes dos veces crea dos clientes. Por eso, al probar, un POST repetido es un caso que siempre vale la pena revisar: ¿se permiten duplicados?
