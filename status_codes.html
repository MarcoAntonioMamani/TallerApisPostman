Status codes HTTP

Cada respuesta de una API trae un código de estado de 3 dígitos. El primer dígito dice la familia: si salió bien, si el error es de quien pide o si el error es del servidor. Es lo primero que se valida en una prueba. Toca una familia para ver sus códigos.
1xx
Informativos“Recibido, sigo procesando.” Casi nunca se ven al probar APIs.
2xx
ÉxitoLa petición se entendió y se procesó correctamente.
3xx
RedirecciónEl recurso está en otro lugar; hay que ir a otra URL.
4xx
Error del clienteLa petición está mal: datos inválidos, sin permiso, no existe.
5xx
Error del servidorLa petición era válida, pero el servidor falló al procesarla.

🎯 ¿Qué código corresponde?

Idea clave: los 4xx significan “revisa lo que enviaste” y los 5xx significan “el problema está del lado del servidor”. Una API bien construida usa el código correcto: devolver 200 con un mensaje de error dentro del body, o 500 cuando en realidad faltaba un dato, es un defecto que también se reporta.
