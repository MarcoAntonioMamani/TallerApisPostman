Mi primer request

Vamos a consultar las mascotas disponibles en Swagger Petstore, revisar la respuesta y guardar el request en una colección. Es el mismo endpoint que viste en la documentación: GET /pet/findByStatus.

Cómo debe quedar

📝 Datos del request 
Método:     GET
URL:        https://petstore.swagger.io/v2/pet/findByStatus?status=available
Params:     status = available   (se llena solo desde la URL)
Auth:       No Auth
Body:       none
Guardar en: colección Taller Petstore
Nombre:     Buscar mascotas por estado
✅ Respuesta esperada 
Status:  200 OK
Time:    menos de 2 s (depende de la red)
Body:    una lista [ … ] de mascotas
         cada una con id, name y status = "available"
Los nombres y la cantidad cambian todo el tiempo: es una API pública y otras personas crean y borran mascotas.

🔍 Para investigar: ¿la API cumple su documentación?

Un estado que no existeCambia el param a status=xyz. La documentación dice que un estado inválido responde 400. ¿Qué responde realmente? 200 OK · []Responde 200 con una lista vacía: no cumple lo documentado. Es un hallazgo.
Un id con letrasPrueba GET https://petstore.swagger.io/v2/pet/abc. La documentación dice 400 Invalid ID. 404 · "java.lang.NumberFormatException: For input string: \"abc\""Responde 404 y además expone un error interno de Java: dos hallazgos en un solo request.
Idea clave: el ciclo siempre es el mismo: armar el request → Send → leer status, tiempo y body → comparar con lo esperado. Y guardar lo que funciona en una colección, para no volver a escribirlo.
