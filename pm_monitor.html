Postman Monitors: vigilar la API las 24 horas

Un monitor ejecuta una colección automáticamente cada cierto tiempo (por ejemplo, cada 15 minutos), desde los servidores de Postman, y lleva un historial: cuántas ejecuciones pasaron, cuánto tardó la API y cuándo falló. Si algo se rompe, avisa por correo u otros canales. Es la diferencia entre enterarse de una caída por un usuario o por una alerta.

Buenas prácticas

🎯 Colección pequeña y rápidaEl monitor no es la regresión completa: usa los requests clave (¿responde?, ¿responde a tiempo?) para que cada ejecución sea liviana.
🧹 Sin dejar basuraSi crea datos, que también los elimine (como nuestro CRUD). Un monitor cada 15 minutos crea 96 registros por día si no limpia.
🔔 Alertas que se atiendenEnvía los avisos a quien puede actuar. Un monitor que falla todos los días sin que nadie lo revise solo genera ruido.
⚠ Como los monitors corren en la nube de Postman, no alcanzan APIs internas y usan los valores compartidos del environment. La cantidad de ejecuciones por mes depende del plan. Para APIs dentro de la red de la empresa, el equivalente es Newman + una tarea programada en un servidor interno, con los resultados en una herramienta de monitoreo.
Idea clave: las pruebas responden “¿funciona después de este cambio?”; el monitor responde “¿sigue funcionando ahora mismo?”. Con la misma colección, una API pasa de probarse cuando alguien se acuerda a estar vigilada todo el tiempo.
