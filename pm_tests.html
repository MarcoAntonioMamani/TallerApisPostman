Scripts y tests

Un script es código JavaScript que Postman ejecuta automáticamente antes o después de cada request. Con ellos se preparan datos, se guardan variables y, sobre todo, se escriben tests: validaciones que convierten “mirar la respuesta” en una prueba automática que dice PASS o FAIL.

En Postman están en la pestaña Scripts → Pre-request / Post-response. En versiones antiguas, Post-response se llamaba Tests.
Pre-request: prepararGenerar datos (ids, nombres, fechas), calcular firmas, obtener o renovar un token, limpiar variables.
Post-response: verificar y guardarEscribir los tests y guardar valores de la respuesta (ids, tokens) para los siguientes requests.

Anatomía de un test

pm.test("Status 200", () => { pm.expect(pm.response.code).to.eql(200); });
pm.testDeclara un test. Cada uno aparece como una línea en Test Results.
El nombreLo que verás en el reporte. Debe decir qué se espera: “Status 200”, “Devuelve el id creado”.
La funciónEl bloque de código que se ejecuta. Si algo falla dentro, el test queda en FAIL.
pm.expectLa aserción: compara el valor real con el esperado. Sin ella, el test pasa siempre.

Aserciones más usadas



  
pm.response.to.have.status(201)El status code es exactamente 201.

  
pm.expect(pm.response.responseTime).to.be.below(1000)Respondió en menos de 1 segundo.

  
pm.response.to.have.header("Content-Type")La respuesta trae ese header.

  
pm.expect(json.name).to.eql("Firulais")Un valor es igual al esperado (también objetos y listas).

  
pm.expect(json).to.have.property("id")El objeto tiene ese campo.

  
pm.expect(json.name).to.be.a("string")El tipo de dato es el correcto: string, number, boolean, array, object.

  
pm.expect(json.status).to.be.oneOf(["available","pending","sold"])El valor es uno de los permitidos.

  
pm.expect(json).to.have.lengthOf.above(0)La lista no está vacía.

  
pm.expect(json.email).to.match(/@/)El texto cumple un patrón (expresión regular).

  
pm.expect(texto).to.include("error")El texto o la lista contiene un valor.

  
pm.response.to.have.jsonSchema(schema)Toda la respuesta cumple un esquema JSON (campos, tipos y obligatorios).




💡 No hace falta memorizarlas: en Postman, al lado del editor de scripts está el panel Snippets, con ejemplos listos para insertar con un clic. Y para depurar, View → Show Postman Console (Ctrl+Alt+C) muestra cada request enviado y lo que imprimas con console.log().



Errores comunes al escribir tests



  
✗
Un test sin pm.expect. Si la función no compara nada, el test siempre pasa, aunque la API esté rota.

  
✗
Leer JSON de una respuesta vacía. pm.response.json() falla si el body está vacío (por ejemplo un 204). Valida primero el status.

  
✗
Validar valores que siempre cambian. Fechas, ids o tokens exactos: valida su tipo o formato, o compáralos con la variable que guardaste.

  
✗
Nombres vagos. “Test 1” o “OK” no dicen nada en un reporte. El nombre debe decir qué falló sin abrir el código.

  
✗
Comparar tipos distintos. pm.environment.get() puede devolver texto: "1001" no es igual a 1001. Convierte con String() o Number().

  
✗
Solo probar el status. Un 200 con datos incorrectos es un defecto. Valida también el body y las reglas de negocio.






  Idea clave: un buen request de prueba responde tres preguntas con tests: ¿respondió lo que debía? (status y tiempo), ¿con la forma correcta? (campos y tipos) y ¿con los datos correctos? (valores y reglas).
  Con eso, ejecutar 100 requests y revisar el resultado toma segundos.
