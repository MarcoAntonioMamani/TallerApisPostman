Mi primer pipeline: el Jenkinsfile

El Jenkinsfile es la receta que Jenkins sigue en cada build. Se escribe en un lenguaje declarativo, se guarda en el repositorio y lo lee Jenkins al iniciar. Este es el del taller, completo: haz clic en cada bloque para entender qué hace. ⬇ Jenkinsfile

💡 Declarativo quiere decir que describes qué quieres (etapas, parámetros, reportes) y Jenkins se encarga del cómo. Las llaves { } deben cerrar siempre: un error de sintaxis hace fallar el build antes de empezar.
1New ItemEn el panel, ＋ New Item. Nombre: pruebas-api-petstore (sin espacios). Tipo: Pipeline → OK.
2Apuntar al repositorioEn la sección Pipeline: Definition Pipeline script from SCM → SCM Git → la URL de tu repositorio de GitHub. Si es privado, elige la credencial del token.
3Rama y archivoBranch Specifier */main y Script Path Jenkinsfile (la ruta del archivo dentro del repositorio). Save.
4El primer build: Build NowLa primera vez Jenkins todavía no conoce los parámetros: los lee del Jenkinsfile en este build, que corre con los valores por defecto. También registra los triggers.
5Desde ahora: Build with ParametersEl botón cambia de nombre y muestra el formulario con los parámetros. Lo vemos en acción en el siguiente tema.
⚠ Script Path distingue mayúsculas: Jenkinsfile no es lo mismo que jenkinsfile. Si Jenkins dice Unable to find Jenkinsfile, revisa el nombre y que el archivo esté subido a la rama main.
Idea clave: el pipeline es código. Si lo cambias, haces commit y push como con cualquier archivo, y queda historial de quién cambió qué. Jenkins solo necesita saber dónde está el repositorio.
