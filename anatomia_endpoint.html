Anatomía de un endpoint

Un endpoint es una dirección concreta de la API donde se puede pedir algo. Se define por dos cosas: el método HTTP y la ruta. GET /clientes/{id} y DELETE /clientes/{id} usan la misma ruta, pero son dos endpoints distintos. Cambia los valores y observa cómo se arma la petición.

Las partes de una petición



  
1 · MétodoIndica la acción: leer, crear, modificar o eliminar. GET, POST, PUT, PATCH, DELETE.

  
2 · URLIndica dónde está el recurso: host, ruta, path params y query params.

  
3 · HeadersDatos sobre la petición: formato (Content-Type), autenticación (Authorization), idioma…

  
4 · BodyLos datos que se envían, normalmente en JSON. Lo usan POST, PUT y PATCH. GET y DELETE normalmente no llevan body.





Path param vs query param



  
Path param — identifica
    
Es parte de la ruta y apunta a un recurso específico. Si falta, la ruta cambia de significado.

    
/clientes/123     → el cliente 123
/clientes           → la lista de clientes

  
Query param — filtra o ajusta
    
Va después del ?, en pares clave=valor unidos con &. Es opcional: filtra, ordena o pagina.

    
/clientes?estado=activo&pagina=2
→ solo activos, segunda página






  Idea clave: en Postman nunca se escribe el host a mano en cada request. Se guarda en una variable como {{baseUrl}}, y cambiar de ambiente (DEV → QA) es cambiar el valor de esa variable, no editar cada petición.
