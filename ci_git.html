Git y GitHub: tu proyecto en un repositorio

Antes de automatizar con Jenkins, las pruebas tienen que vivir en un repositorio. Git guarda el historial de cada cambio en tu PC; GitHub guarda una copia en la nube que comparte el equipo… y desde donde Jenkins descarga las pruebas para ejecutarlas.

📁Carpeta de trabajo

Tus archivos tal como los ves en el explorador. Aquí editas.

📋Staging

Los cambios que elegiste para el próximo commit.

🗃️Repositorio local

El historial: cada commit es una “foto” con mensaje, autor y fecha.

☁️GitHub (remoto)

La copia compartida. Jenkins descarga de aquí.
git add
Presiona los botones en orden para ver el viaje de un cambio, desde tu PC hasta GitHub.

Vocabulario mínimo

📦RepositorioCarpeta del proyecto con todo su historial de cambios.
📸CommitUn punto guardado en el historial, con un mensaje que explica qué cambió.
🌿Rama (branch)Una línea de trabajo. La principal se llama main.
🔗Remoto (origin)La copia del repositorio en GitHub.
⬆️pushEnviar tus commits al remoto.
⬇️pullTraer los commits nuevos del remoto a tu PC.
📥cloneDescargar un repositorio completo por primera vez. Es lo que hace Jenkins.
🙈.gitignoreLista de lo que Git no debe subir: dependencias, reportes, secretos.
1Descargar Git para WindowsEntra a git-scm.com → Download for Windows. Instala con las opciones por defecto: incluye Git Bash y el Git Credential Manager, que guarda tu inicio de sesión de GitHub.
2VerificarAbre una terminal nueva y revisa la versión.
3Decirle a Git quién eresCada commit lleva nombre y correo. Se configura una sola vez por PC con --global. Usa el mismo correo de tu cuenta de GitHub.
4Rama principal: mainHace que los repositorios nuevos empiecen en main, el mismo nombre que usa GitHub.
5Revisar la configuracióngit config --list muestra lo que quedó guardado.
6Red corporativa con proxySi git push no logra conectarse, la red puede exigir un proxy. Pide la dirección a soporte y configúrala. No escribas tu contraseña dentro de la URL del proxy.

1Entrar a la carpeta del proyectoCon la colección y el environment exportados desde Postman, más los datos, el package.json, el Jenkinsfile y el .gitignore.

      
2git initConvierte la carpeta en un repositorio (crea la carpeta oculta .git).

      
3git statusEl comando que más usarás: muestra qué cambió y qué falta guardar. Fíjate que node_modules no aparece: lo excluye el .gitignore.

      
4git add + git commitgit add . pasa todo a staging y git commit -m "…" crea la primera foto del historial. Escribe mensajes que expliquen qué y por qué.

      
5Conectar con GitHubgit remote add origin <URL> le dice a Git dónde está la copia remota.

      
6git pushSube los commits. La primera vez se abre el navegador para iniciar sesión en GitHub (Credential Manager) y queda recordado. -u enlaza tu rama con la remota: luego basta git push.

      
7VerificarRecarga la página del repositorio en GitHub: ahí están tus archivos. git log --oneline muestra el historial.

1Cambias la colección en PostmanAgregas un test, lo pruebas y vuelves a exportar la colección encima del archivo de la carpeta postman/.

      
2Revisas qué cambiógit status y git diff muestran exactamente las líneas modificadas, antes de guardarlas.

      
3Guardas y subesadd → commit → push. Jenkins usará esta versión en su próxima ejecución.

      
4Traes cambios de otrosSi alguien más subió cambios, git pull los descarga y los une con los tuyos.

      
5Error: rejectedGitHub tiene commits que tú no tienes. Primero git pull --rebase, después git push.

      
6Subí un secreto por errorBorrarlo en un commit nuevo no basta: sigue en el historial. Lo correcto es revocar y cambiar ese token o clave de inmediato.

Idea clave: el repositorio es la única fuente de verdad de tus pruebas. Lo que está en GitHub es lo que Jenkins ejecuta: si no hiciste push, Jenkins no se entera del cambio.
