Controlar el orden de ejecución

Por defecto, el Runner ejecuta los requests de arriba hacia abajo. A veces hace falta más control: detener todo si el login falla, saltar un request, o repetir uno hasta que la API termine de procesar. Hay tres formas de controlarlo, de la más simple a la más flexible.
1 · El orden en la colecciónLos requests se ejecutan en el orden en que están en la carpeta. Por eso los nombres llevan número: 01 Crear, 02 Consultar… Arrastra para reordenar.
2 · El Run order del RunnerAntes de ejecutar puedes desmarcar requests o arrastrarlos para cambiar el orden solo de esa ejecución, sin tocar la colección.
3 · Con scriptsDecidir durante la ejecución qué request sigue, según la respuesta: pm.execution.setNextRequest() y pm.execution.skipRequest().

Las instrucciones



  
pm.execution.setNextRequest("02 Consultar mascota")Al terminar el request actual, salta al request con ese nombre exacto, esté antes o después.

  
pm.execution.setNextRequest(null)Detiene la ejecución después del request actual.

  
pm.execution.skipRequest()En un Pre-request: no envía el request actual y pasa al siguiente.

  
postman.setNextRequest(…)Forma anterior, equivalente. La verás en colecciones antiguas.




⚠ Estas instrucciones solo funcionan al ejecutar con el Collection Runner, Newman o la Postman CLI. Si envías un request suelto con Send, se ignoran. Y en un ciclo, usa siempre un contador con un máximo: un ciclo sin salida ejecuta requests sin fin.




  Idea clave: el orden normal es de arriba hacia abajo, y casi siempre basta con numerar bien los requests. Usa scripts solo cuando el flujo realmente dependa de la respuesta:
  detener si un paso crítico falla, saltar lo que no aplica o reintentar mientras la API termina un proceso.
