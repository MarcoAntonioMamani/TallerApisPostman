Ejecutar desde la terminal (CLI)

Una CLI (Command Line Interface, interfaz de línea de comandos) es una forma de usar un programa escribiendo comandos en una terminal, en lugar de hacer clic en botones. Ejecutar la colección por CLI permite que corra sin abrir Postman: en un servidor, en una tarea programada o en un pipeline de Jenkins.
🖱 Con interfaz gráfica
Abrir Postman → elegir colección → Runner → configurar → Run. Necesita una persona frente a la pantalla.
⌨ Con CLI
Un solo comando hace todo lo anterior: newman run coleccion.json -e environment.json. Lo puede ejecutar una máquina, sola, cada vez que haga falta.

Dos herramientas

📦 NewmanLa herramienta clásica y de código abierto. Ejecuta colecciones exportadas como archivos .json. No necesita cuenta de Postman. 
# Requiere Node.js
npm install -g newman
npm install -g newman-reporter-htmlextra   # reporte HTML
🧰 Postman CLILa herramienta oficial de Postman. Ejecuta colecciones directamente desde tu cuenta (por id) y envía los resultados a Postman. 
# La API key va en una variable de entorno, nunca en el script
postman login --with-api-key $POSTMAN_API_KEY
postman collection run <id-de-la-coleccion> -e <id-del-environment>

Paso 1 · Exporta la colección y el environment

Newman no se conecta a tu cuenta de Postman: ejecuta archivos. Por eso, primero se exportan la colección y el environment como .json a una carpeta del proyecto, por ejemplo C:\taller-postman.
☁ Postman 12: comparte antes de exportar. Los valores de un environment se guardan solo en tu PC hasta que haces clic en ☁ Share junto a cada uno. Export solo incluye los valores compartidos: sin ese paso, el archivo sale con baseUrl vacío y Newman no puede ejecutar nada. Abre el .json exportado y confirma que baseUrl tenga su valor.
⚠ Antes de exportar el environment, revisa sus valores: el archivo queda en texto plano. Una clave real no debe quedar en el archivo ni subirse a un repositorio: déjala vacía y pásala al ejecutar con --env-var "apiKey=…" (lo verás en Newman a fondo). La special-key de Petstore es pública, por eso en el taller no hay problema.
🧭 Postman cambia sus menús entre versiones. Si no encuentras Export directamente en el menú ⋯, búscalo en More → Export collection → Other.
💡 Cada vez que cambies la colección en Postman, vuelve a exportarla sobre el mismo archivo: Newman ejecuta la versión del archivo, no la de tu Postman.

Paso 2 · Ejecuta en la terminal

Abre el Símbolo del sistema, entra a la carpeta con cd C:\taller-postman y ejecuta. Empieza por Revisar la carpeta.
Símbolo del sistema — C:\taller-postman





Opciones más usadas de Newman



  
-e "Petstore - QA.postman_environment.json"El environment a usar (baseUrl, apiKey…).

  
--folder "CRUD Mascota"Ejecutar solo una carpeta.

  
-n 3Cantidad de iteraciones.

  
-d datos/mascotas.csvArchivo de datos (CSV o JSON): una iteración por fila.

  
--delay-request 200Espera en milisegundos entre requests.

  
-r cli,junit,htmlextraReportes: en pantalla, JUnit XML (para Jenkins) y HTML (para humanos).

  
--bailDetener todo al primer error.

  
--insecureNo validar el certificado SSL. Solo en ambientes de prueba con certificados internos, nunca contra producción.




💡 El código de salida es lo que entiende una máquina: 0 si todos los tests pasaron y 1 si alguno falló. Así Jenkins marca el build en verde o en rojo sin que nadie lea el reporte.



En un pipeline de Jenkins


pipeline {
  agent any
  stages {
    stage('Pruebas de API') {
      steps {
        bat 'newman run "postman/Taller Petstore.postman_collection.json" -e "postman/Petstore - QA.postman_environment.json" -r cli,junit --reporter-junit-export reports/newman.xml'
      }
    }
  }
  post { always { junit 'reports/newman.xml' } }   // publica el resultado de cada test
}


En el taller usamos bat porque el agente es Windows; en Linux sería sh. Los secretos (como la API key de un ambiente real) se inyectan desde las credenciales de Jenkins, nunca escritos en el archivo.



⚠ Newman necesita Node.js instalado. En equipos corporativos, la instalación de software suele requerir una solicitud a soporte; consúltalo antes del taller si quieres que los estudiantes lo ejecuten en sus máquinas.




  Idea clave: la colección es la misma en Postman y en la terminal. La CLI solo cambia quién la ejecuta: en lugar de una persona presionando Run, un comando que corre solo, en cualquier máquina dentro de la red y en cada despliegue.
