Allure Report: reportes que se entienden

Allure es una herramienta open source que convierte los resultados de las pruebas en un reporte web interactivo: gráficos, el detalle paso a paso de cada test, la clasificación de los fallos y, sobre todo, el historial entre ejecuciones. Funciona con muchas herramientas (Newman, Karate, Selenium, JUnit, Pytest…), así que un equipo puede tener un mismo tipo de reporte para todas sus pruebas.
📊 Resumen visualCuántos tests pasaron, fallaron o se rompieron, de un vistazo.
📈 TendenciaCompara con las ejecuciones anteriores: ¿estamos mejor o peor que ayer?
🔎 Detalle por testCada assertion como un paso, con el mensaje de error y la duración.
🗂 CategoríasSepara fallos de producto (la API respondió mal) de fallos técnicos (el test no pudo ejecutarse).

Allure trabaja en dos pasos: primero se juntan los resultados crudos y después se genera el reporte a partir de ellos.

Instalar y generar el reporte (Windows)

1JavaAllure 2 necesita Java (8 o superior). Verifica con java -version; si no está, instala un JDK (por ejemplo Eclipse Temurin) o pide a soporte que lo instale.
2Instalar AllureComo ya tienes Node.js, la forma más simple es npm install -g allure-commandline. Alternativa: descargar el .zip desde el GitHub de Allure y agregar su carpeta bin al PATH.
3Reporter de Newmannpm install -g newman-reporter-allure permite que Newman escriba resultados en formato Allure.
4Ejecutar con Newman-r cli,allure --reporter-allure-export allure-results. Cada request queda como un test y cada pm.test como un paso.
5Generar y abrirallure generate allure-results --clean -o allure-report y luego allure open allure-report. Atajo para ver rápido: allure serve allure-results.
6Conservar el historialLa tendencia necesita las ejecuciones anteriores: antes de generar, copia allure-report\history dentro de allure-results.
Símbolo del sistema — C:\taller-postman




💡 Existe una versión más nueva, Allure 3, que funciona sobre Node.js y no requiere Java. Revisa su estado y compatibilidad con el reporter de Newman antes de adoptarla; en el taller usamos Allure 2.

Con Jenkins



  
Jenkinsfile

stage('Pruebas de API') {
  steps {
    bat 'newman run "postman/Taller Petstore.postman_collection.json" -e "postman/Petstore - QA.postman_environment.json" -r cli,allure --reporter-allure-export allure-results'
  }
}
post {
  always {
    allure results: [[path: 'allure-results']]   // plugin "Allure" de Jenkins
  }
}

  
Lo que agrega JenkinsCon el plugin Allure, cada build publica su reporte y el plugin se encarga solo del historial: la tendencia muestra cómo evolucionan las pruebas build tras build, sin copiar carpetas a mano.
    
💡 En tu PC usa los scripts del package.json del taller: npm run test:allure y npm run allure:reporte.






  Idea clave: el reporte HTML de Newman muestra una ejecución; Allure muestra la historia: qué falló, por qué, desde cuándo y si es un problema de la API o de la prueba.
  Es el reporte que se comparte con el equipo y con quien toma decisiones.
