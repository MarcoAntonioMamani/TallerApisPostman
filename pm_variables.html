Variables y environments

Una variable guarda un valor con un nombre y se usa escribiéndolo entre llaves dobles: {{baseUrl}}. Un environment es un conjunto de variables para un ambiente (DEV, QA…). Con ellas, la misma colección funciona en cualquier ambiente sin editar ningún request: así trabaja un equipo de QA profesional.

¿Por qué usar variables?

✗ Sin variables
La URL está escrita en cada request. Cambia el servidor y hay que editar todos, uno por uno.
✓ Con variables
La URL base vive en el environment. Para cambiar de ambiente se elige otro environment y listo.

Initial value vs. Current value

Initial valueCurrent value
¿Qué es?El valor “oficial” que se guarda en la colección o environment.El valor que se usa al enviar. Puedes cambiarlo sin afectar a nadie.
¿Se comparte?Sí: se sincroniza con tu equipo y se exporta.No: queda solo en tu máquina.
¿Qué poner?Valores comunes y no sensibles: URLs, ids de prueba.Tus tokens y claves, y los valores que generan los scripts.
🔐 Marca como tipo secret las variables con claves o tokens (se ocultan en pantalla) y deja vacío su Initial value. Así nunca se suben a la nube ni se exportan por accidente.

Variables dinámicas: datos nuevos en cada envío

Postman trae variables que empiezan con $ y generan un valor distinto cada vez que se envía el request. Sirven para no repetir datos de prueba.
VariableGeneraEjemplo
Usadas en un body 
{
  "id": {{$randomInt}},
  "name": "{{$randomFirstName}}",
  "status": "available",
  "tags": [{ "name": "{{$guid}}" }]
}

Crear y leer variables desde un script




// Guardar (por ejemplo, el id que devolvió la API)
pm.environment.set("petId", json.id);        // en el environment activo
pm.collectionVariables.set("petId", json.id);  // en la colección
pm.globals.set("autor", "QA");              // global (todo el workspace)

// Leer: pm.variables.get busca en todos los alcances y respeta cuál gana
const id = pm.variables.get("petId");

// Obtener un valor dinámico dentro de un script
const nombre = pm.variables.replaceIn("{{$randomFirstName}}");

  
Esto es lo que permite que un request use datos creados en tiempo de ejecución por otro request. Lo aplicaremos en el CRUD completo, en el siguiente tema.





Buenas prácticas



  
🏷 Nombres clarosUsa camelCase y nombres que digan qué son: baseUrl, petId, accessToken.

  
🌍 Un environment por ambienteLas mismas variables, con distinto valor: Petstore - DEV, Petstore - QA. Nunca mezclar ambientes en uno.

  
🧭 Cada cosa en su alcanceURLs y claves → environment. Datos de la colección → collection. Globals solo para lo realmente general.






  Idea clave: un request profesional casi no tiene valores escritos a mano: {{baseUrl}} para el servidor, variables secretas para las credenciales, {{$random…}} para los datos y variables guardadas por scripts para encadenar requests.
  Si alguien te pasa la colección, solo tiene que elegir su environment y presionar Send.
