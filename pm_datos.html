Datos de prueba desde archivos CSV y JSON

Hasta ahora cada request tenía un juego de datos. Con un archivo de datos, el mismo request se ejecuta una vez por cada fila: cada fila es una iteración y cada columna se convierte en una variable. A esto se le llama pruebas data-driven (dirigidas por datos): agregar un caso de prueba es agregar una fila, sin tocar la colección.

Cómo funciona

📄 mascotas.csv · cada fila = una iteración
📨 El request usa las columnas como variables 

    





Los dos formatos



  
CSV · la primera fila son los nombres de las variables

nombre,categoria,status
Firulais,Perros,available
Michi,Gatos,pending
Rocky,Perros,sold
Luna,Gatos,available
Kira,Perros,perdida

    
Simple y fácil de editar en Excel. Todos los valores llegan como texto.

    ⬇ Descargar mascotas.csv

  
JSON · una lista de objetos, uno por iteración

[
  { "nombre": "Firulais", "categoria": "Perros", "status": "available" },
  { "nombre": "Michi",    "categoria": "Gatos",  "status": "pending" },
  …
]

    
Permite números, booleanos y objetos (por ejemplo, un body completo por fila).

    ⬇ Descargar mascotas.json





Usar los datos en el request y en los scripts



  
En URL, headers y bodyIgual que cualquier variable: {{nombre}}, {{status}}. Las variables de datos tienen prioridad sobre las del environment (alcance Data).

  
En los scriptspm.iterationData.get("nombre") devuelve el valor de la fila actual. Ideal para que el resultado esperado también venga del archivo.

Errores comunes



  
✗ Nombres que no coincidenLa columna se llama Nombre y el body usa {{nombre}}: no se reemplaza. Mayúsculas y tildes cuentan.

  
✗ Ejecutar toda la colecciónCon el archivo cargado, todos los requests se repiten por cada fila. Ejecuta solo la carpeta que usa los datos.

  
✗ CSV mal guardadoGuárdalo como CSV UTF-8 para no perder las tildes, y cuidado con las comas dentro de un valor: ese valor va entre comillas.






  Idea clave: el request es la plantilla y el archivo trae los casos. Con 5 filas probamos 5 combinaciones y apareció un defecto real: la fila de Kira usa un estado que la documentación no permite (perdida), y la API lo acepta igual.
